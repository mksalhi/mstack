# Experience first

**Rule:** Favor user delight and fewer, polished features.

When implementation convenience conflicts with user delight, choose delight.

- Every feature, control and option must justify itself; three polished features beat ten rough ones.
- Every feature serves the core loop or gets out of the way.

The user is whoever consumes the work: the end user for a UI, the importing colleague for a library or internal API, and the next maintainer. Weigh their experience equally; explain impact from their perspective.

To settle a design question with competing prototypes, use [Exhaust the design space](exhaust-the-design-space.md).
