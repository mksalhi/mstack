Match surrounding voice. Flag only inconsistency, ambiguity, translation risk, or tone that doesn’t fit the stakes. Errors and destructive actions: plain, calm, never playful. Rendering: [typography](typography/index.md); error markup: [accessibility](accessibility/index.md); longer strings: [layout](layout/index.md).

- One term per concept; keep flow vocabulary consistent: Get started → Continue or Next (pick one) → Done.
- Address the reader as “you”; in errors avoid “we” (e.g., “Unable to load content”).
- Buttons start with a verb and repeat the consequence. Confirmations offer the action and Cancel; never Yes/No/OK for consequential actions.
- Links read on their own; never “Click here”.
- Toggles describe the ON state.
- Errors sit by the field and say how to fix; no blame or exclamation marks.
- Never concatenate around a variable; use one templated string with plural rules.
- Placeholders are examples (e.g., name@example.com), never labels.

Severity:
- HIGH: misleads the user or hides how to recover.
- MEDIUM: inconsistent terms or capitalization.
- LOW: wording polish.

Use the format in [review](review/index.md#output).
